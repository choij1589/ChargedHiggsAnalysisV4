# PLAN: trigger efficiencies and scale factors for 2024 (phase 2.4)

Goal: measure the efficiencies of the dimuon and e-mu triggers of the analysis in 2024 data and simulation, build the per-event trigger SF, check it with a closure test, and apply it in DiLepton (and later TriLepton). Reference: B2G-25-013 (AN-25-154 `Sections/Trigger.tex`, `Appendix/Trigger.tex`; old SKNano `Analyzers/src/MeasTrigEff.cc`, `ClosDiLepTrigs.cc`, `AnalyzerTools/src/MyCorrection.cc`; V3 `MeasTrigEff/python/`). Written 2026-11-25 from two surveys (sources in `LOG_Trigger.md`); decisions go to `LOG_Trigger.md`.

## 1. What is reproduced

| Item | B2G-25-013 (Run 3) | 2024 |
|---|---|---|
| Paths | DiMu: `Mu17_TrkIsoVVL_Mu8_TrkIsoVVL_DZ_Mass3p8`; EMu: `Mu8_TrkIsoVVL_Ele23_CaloIdL_TrackIdL_IsoVL_DZ` OR `Mu23_TrkIsoVVL_Ele12_..._DZ` | same; all in the 2024 menu and in our RNTuples, as are their non-DZ (and non-Mass) versions (Muon0/1, MuonEG) |
| Factorisation | per-object legs x pairwise filters (DZ, Mass3p8); SF = eff(data)/eff(MC) per event | same |
| Dimuon legs | Mu17 (leg 1), Mu8 (leg 2): tag and probe on Z->mumu, IsoMu24 tag, fit (MC template x Gaussian + RooCMSShape) | same, from our existing TnP ntuples: `probe_Mu17Leg1` / `probe_Mu8Leg2` = trigger object with filter bit 4 ("2mu") and pT > 17 / 8 GeV, dR < 0.1; fitted with tnp_tamsa (NanoV15) |
| e-mu legs | reference-trigger method, cut and count: electron legs in e-mu events tagged by IsoMu24 (Muon PD), muon legs tagged by Ele30 (EGamma PD); MC TTto2L2Nu powheg | same, new analyzer; legs = muon bit 5 ("1mu-1e") / electron bit 6 ("1e-1mu") + trigger-object pT (Mu23/Mu8, Ele23/Ele12) |
| Pairwise filters | DZ, Mass3p8 (dimuon) and DZ (e-mu) from ratios of path decisions, inclusive per era, no uncertainty | same method; uncertainty to decide (T6) |
| Per-event formula | AN: legs x DZ with the "same object" correlation; code: e-mu legs picked by pT (not the AN formula, not a true OR) | T1 |
| Closure | MC: expected (legs) vs observed (path decision), DY / tt / signal; e-mu Run 3 DY off by 3-5% | same (new analyzer or DiLepton histograms) |
| Uncertainty in the fit | flat 2% (dimuon) / 3% (e-mu) from the closure, by era | T3 |

What NanoAODv15 allows (survey, `LOG_Trigger.md`): filter bits give one bit per trigger class, so legs are separated only by the trigger-object pT (as in B2G-25-013 Run 3), and DZ / Mass3p8 have no bit of their own (path ratios). The e-mu L1 seeds need an EG object, so e-mu legs cannot come from Z->mumu or Z->ee probes (Z->ee probes carry the e-mu electron legs 0.2% of the time).

## 2. Design

- **Dimuon legs (no new production):** tnp_tamsa configs on the existing muon TnP RNTuples (`/d0/scratch/choij/TnP/2024/rntuple/muon/`): denominator = our tight muon (probe) with the ID-SF tag setup; numerators `probe_Mu17Leg1`, `probe_Mu8Leg2`; nominal MC DYto2Mu 4J (LO), as for the ID SFs; systematics as the ID SFs (MUO set: tag iso, mass bins, mass range, alt signal MC, alt background). Binning |eta| [0, 0.9, 1.2, 2.1, 2.4] x pT around the thresholds (B2G-25-013: Mu17 [10, 14, 16, 18, 20, 25, 30, 40, 50, 100, 200], Mu8 [10, 15, 20, 25, 30, 40, 50, 100, 200]).
- **e-mu legs and pairwise filters (new analyzer `MeasTrigEff`, `HcToWA_Analyzers`):** exactly one tight muon and one tight electron (our IDs), opposite sign, dR > 0.4; electron legs: IsoMu24 fired and matched to the muon (bit 3, pT > 24), offline pT(mu) > 26, on Muon0/1; muon legs: Ele30 fired and matched (bit 18) with offline pT(e) > 32, on EGamma0/1; num/den histograms per leg in (|eta|, pT); MC TTto2L2Nu powheg (+ alternative MC). Pairwise: dimuon events firing the plain path with both muons matched to bit-4 objects (pT > 17, > 8): fraction firing `_DZ`, `_DZ_Mass3p8`; e-mu events firing a non-DZ path in its pT region: fraction firing the DZ version.
- **Output:** correctionlib JSON per leg (`data`, `sim`, `sf`; nom/up/down) and the pairwise numbers in a data file (not C++ constants), in `HcToWA_Analyzers/data/2024/Trigger/`; `HcToWABase` builds the per-event SF; DiLepton lanes `DblMuTrigSF`, `EMuTrigSF` (+ `_NotImplemented`).
- **Closure:** MC histograms of expected (legs) and observed (path decision) efficiency in DiMu, EMu and the trilepton baselines (signal, WZ, ttZ, DY, tt).

## 3. Steps and gates

1. Dimuon legs: tnp_tamsa configs, fits, fit check, maps and 1D plots, comparison with MUO where possible (MUO has no dilepton-leg SFs for 2024; the B2G-25-013 2022/2023 legs as a sanity reference). **Gate:** user review.
2. `MeasTrigEff` analyzer (e-mu legs + pairwise filters), one-file tests, production on data (Muon0/1, EGamma0/1) and MC (TTLL powheg + alternative). **Gate:** efficiencies and their statistics per bin.
3. Per-event SF (T1), JSONs, closure test in MC. **Gate:** closure within the assigned uncertainty.
4. Application in DiLepton (DIMU, EMU), data/MC before/after. **Gate:** user review.
5. Record in `LOG_Trigger.md`; AN section via `/an-section-update Trigger`.

## 4. Open decisions (user)

- **T1 (decided, user 2026-11-25):** per-event efficiency from per-object leg probabilities and the path logic, as a true OR of the paths. Assumptions: nesting within an object (Mu23 => Mu8, Ele23 => Ele12, Mu17 => Mu8; exact for our pT-threshold leg definitions) and independence between objects (checked by the MC closure). Implementation: enumerate the 3^N joint states of the leptons (pass tight leg / pass loose leg only / fail) and sum the probabilities of the states that fire a path; closed form for e-mu: eps = [M23 E12 + M8 E23 - M23 E23] x eps_DZ with M_x = 1 - prod(1 - m_x,i), E_x likewise (eu: m23 e12 + m8 e23 - m23 e23); dimuon: one muon passes Mu17 and a different one Mu8, x eps_DZ x eps_Mass3p8 (includes the mu mu mu case missing from the AN-25-154 formula). SF = eps_data / eps_MC. Validation: MC closure (DY, tt, e mu mu / mu mu mu signal, WZ) and comparison with the B2G-25-013 pT-picked formula on the same events.
- **T2 (decided, user 2026-11-25):** e-mu legs: statistical (Clopper-Pearson for data; weighted binomial with sum w and sum w^2 for MC) (+) alternative MC (MC efficiency with DY instead of TTLL powheg; the planned TTLL amc@NLO alternative does not exist for 2024, LOG_Trigger 2026-11-25 steps 1 and 2). No AltTag (tag-selection variation, not recommended by the Statistics Committee); instead two checks, assigned only if significant: non-prompt contamination (data efficiency with and without subtracting same-sign e-mu events) and reference-trigger bias (MC leg efficiency in all e-mu events vs in reference-triggered events). Dimuon legs: the ID-SF fit systematics (mass bins, fit range, alternative signal and background, alternative MC; tag isolation as MUO). Pairwise filters: statistical (+) alternative MC.
- **T3 (decided, user 2026-11-25; revised the same day):** one nuisance per trigger SF (dimuon, e-mu), since these uncertainties are small compared to the other systematics (user). Up/down = data efficiencies of all legs and pairwise filters up/down with the MC efficiencies down/up, coherent in all bins; the closure term (largest |observed/expected - 1| over the MC closure samples DY, tt, signal, WZ with the T1 formula) is added in quadrature event by event to the relative SF variation. **Revised (user, 2026-11-26): no closure term.** The closure is a check that must pass within the uncertainty from the measurements; the pairwise (DZ) filters, one inclusive number each, carry the spread of their binned SFs as uncertainty (`LOG_Trigger.md`). DiLepton lanes `DblMuTrigSF`, `EMuTrigSF` (Up/Down, + `_NotImplemented`). (First version: four nuisance groups plus a separate flat closure term.)
- **T4 (decided, user 2026-11-25):** legs binned in the scale/smear-corrected pT (as the ID SFs, L4 revised) and looked up with `Pt()`; the analyzers store the uncorrected pT as well, so the turn-on widths can be compared and the closure test shows any binning bias near the thresholds (offline mu > 10 GeV vs Mu8, e > 15 GeV vs Ele12).
- **T5 (decided, user 2026-11-25):** electron leg = trigger object with bit 6 ("1e-1mu") AND bit 0 ("CaloIdL_TrackIdL_IsoVL", the leg's last filter) and pT > 12 / 23 GeV; the electron-leg denominator requires the IsoMu24 tag muon to pass the muon leg of the same path (bit 5 with pT > 23 for Ele12, > 8 for Ele23), because the e-mu electron filters run only after the muon leg and an unconditioned efficiency would count the muon-leg inefficiency twice in the per-event product. The analyzer also stores bit 6 alone and the unconditioned denominator, to measure both effects.
- **T6 (decided, user 2026-11-25):** each pairwise filter (dimuon DZ, Mass3p8 / DZ_Mass3p8; e-mu DZ per path) measured inclusively from path-decision ratios, with statistical (+) alternative-MC uncertainty (nuisance `TrigPairFilter`, T3); also binned in the larger |eta| of the pair (and in pT) as a check: if flat within statistics the inclusive value is used, otherwise the binned one. Values in a data file under `data/2024/Trigger/` (no C++ constants).
- **T7 (decided, user 2026-11-25):** muon legs referenced by `HLT_Ele30_WPTight_Gsf` (EGamma0/1), matched with electron bit 18 (specific to Ele30), offline electron pT > 32 GeV; electron legs by `HLT_IsoMu24` (Muon0/1), matched with muon bit 3 and pT > 24, offline muon pT > 26 GeV. Prescales are not available locally; both are standard unprescaled 2024 paths (EGM provides 2024 Ele30 SFs).

All open decisions T1-T7 settled (2026-11-25). Revised 2026-11-26 (user): e-mu legs and pairwise filters without alternative-MC uncertainty (DY for reference only); pairwise filters as one inclusive number each (dimuon DZ, e-mu DZ); e-mu binning as in `Trigger/python/measEMuEff.py`.
