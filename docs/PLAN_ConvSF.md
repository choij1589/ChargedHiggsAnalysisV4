# PLAN: conversion background and its scale factor for 2024 (phase 3.4)

Goal: measure the conversion scale factor (ConvSF) per channel in a Z gamma control region with the 2024 data, as B2G-25-013 did per era, with the 2024 objects, corrections and nonprompt estimate. Written 2026-11-27 from a survey of AN-25-154, B2G-25-013 and the V3/SKNanoAnalyzer code (sources below with file:line; paths relative to `docs/previous_analysis/`). Decisions C1-C6: all decided 2026-11-27 (user).

Known mismatches in the old analysis (survey 2026-11-27), not to be carried over:
1. The CR conversion filter tested only DYJets / TTG (`PromptAnalyzer.py:661`), so WWG was unfiltered in the Run 2 ZG CR but filtered in the SR.
2. The AN says leptons from hadrons or with charge flip are removed from the conversion samples (`Dataset.tex:435`); the code only requires one conversion lepton.
3. The nonprompt and theory components used only |up - central| (`measConvSF.py:335, 354`), while the AN describes up/down variations.

## 2. Design

- **TriLepton analyzer** (C++, `HcToWA_Analyzers`, first part of the PLAN 1 port; needed anyway for the SR and the WZ CR). Selection as the ClosFakeRate analyzer (2026-11-27; shared code moved to a common base or helpers), regions SR, ZG CR, WZ CR (MET > 40 GeV, on-Z OS pair, as B2G), channels by flags (Run1E2Mu, Run3Mu). Two modes:
  - **prompt MC:** all leptons tight; weights MCweight x lumi x PU x lepton ID SFs x trigger SF (DblMu / EMu, T1) x b-tag weight (method 1a; N_b = 0 in the ZG CR); truth category per event (conversion / prompt / fake / charge flip) from the GetLeptonType port; systematic lanes as DiLepton (later).
  - **nonprompt:** data with >= 1 loose-not-tight lepton, the fake weight of `fakerate_HcToWA.json` (Central, Total_Up, Total_Down).
- **Samples (Skim_TriLep, done 2026-11-27):** data MuonEG, Muon0/1; conversion C1; prompt: WZ (FxFx, per PLAN 3.5, or POWHEG), ZZto4L, ttW / ttZ / ttH, tZq, tWZ, tHq, tHW, tribosons, VH, ggH/VBF H -> ZZ, TTTT.
- **measConvSF.py** (`TriLepton/python/` in this repo): yields in the ZG CR per channel, SF and uncertainty components, correctionlib JSON (`ConvSF`: channel, syst), plots of the ZG CR with and without the SF, m(3l) and the conversion-lepton kinematics.

## 3. Steps and gates

1. TriLepton analyzer, CR part: implementation, condor tests on a few files (data, DY, TTG, WZ). **Gate:** cutflows, truth categories of the conversion samples (fraction internal / external / other), timing.
2. Production on the Skim_TriLep data and MC (prompt mode) and data (nonprompt mode). **Gate:** ZG CR data / prediction before the SF, composition.
3. ConvSF per channel with the uncertainty components; JSON. **Gate:** user review of the numbers and plots.
3a. **Done 2026-11-27:** e mu mu 0.759 +- 0.078, mu mu mu 0.947 +- 0.126, accepted (user); JSON installed. Open for the next iteration (after the final limits): the DYGto2LG comparison (C1 (b)) with a fixed DY overlap removal for internal conversions.
4. Record in `LOG_BkgEst.md`; AN subsection (Conversion background) and appendix ZG CR via `/an-section-update BkgEst conversion`.

## 4. Open decisions (user)

- **C1 (conversion samples):** (a) as B2G: DY 2J + TTG (Z gamma and tt gamma from QED radiation in the DY and tt samples); (b) DYGto2LG (dedicated Z gamma, more conversion events) + TTG, with an overlap removal against DY (generator photon above the DYG threshold removed from DY); (c) (a) nominal, (b) as a cross-check of the SF. **Decided (user 2026-11-27): (c).** All samples are skimmed (Skim_TriLep). TTG is stitched on the generator photon pT (inclusive < 100 GeV, PTG100 100-200, PTG200 > 200; the 2024 samples overlap, unlike the exclusive 2022 bins of B2G). The DYG photon cuts for the DY overlap removal are taken from the gridpack or the generator photons in step 1 (the McM public API does not return the GS fragment of these chains). DYG adds statistics for e mu mu (external conversions of real photons); mu mu mu (internal conversions, gamma* -> mu mu from the shower) stays on DY. Step-1 check: possible overlap of DY (shower gamma* -> mu mu) with the Z -> 4l part of ZZto4L near m(3l) = m_Z.
- **C2 (truth matching):** port GetLeptonType (internal types 4/5, external -5/-6 with the photon match pT > 10 GeV, |dpT/pT| < 0.5, dR < 0.2) and use one filter for SR and CR in every conversion sample: >= 1 tight lepton of a conversion type; events of the conversion samples without one are dropped (they are prompt or nonprompt, counted elsewhere). Proposed as written (fixes mismatches 1 and 2 by applying the filter consistently; no extra veto on the other leptons, as the code did). **Decided (user 2026-11-27): with a veto** (option b): an event of a conversion sample is kept only if >= 1 tight lepton is of type 4, 5, -5 or -6 and no other lepton is of type -1 to -4 (hadronic origin or unmatched), as the B2G AN text describes; this avoids double counting with the data-driven nonprompt estimate. Same filter in SR and CR for DY, TTG and DYGto2LG; prompt MC unfiltered (as B2G). Step-1 gate: fraction removed by the veto, fraction of type 0 (GenPart pruning in v15), electron types -5/-6 vs Electron_genPartFlav == 22.
- **C3 (ZG CR selection):** as B2G (above), on the 2024 objects. Proposed as B2G. **Decided (user 2026-11-27): the B2G selection, unchanged** (2024 object definitions only); no extra diagnostics beyond the standard ZG CR plots (the conversion background is a small part of the background, user).
- **C4 (uncertainty):** stat (+) nonprompt (F1 nuisance: SF with the Total_Up / Total_Down rates) (+) theory (cross-section uncertainty of each prompt group, up and down, 50% fallback), the larger of up/down per component; one lnN per channel in the fit, correlated with nothing else; e mu mu and mu mu mu uncorrelated. Proposed as written. **Decided (user 2026-11-27): as proposed (larger of up/down per component).** Nonprompt component from the SF with the Total_Up / Total_Down rates (the anticorrelation with the fake-rate nuisance in the fit is neglected, as B2G). Theory: B2G Run 3 `xsecErr` (`ChargedHiggsAnalysisV3/Common/Data/KFactors.json`: ggZZ 15%, ttZ 7.5%, ttW 12%, ttH 10%, tZq 3.5%), 50% fallback for the rest, except **WZ: its theory uncertainty instead of the 50% fallback** (user; B2G Run 3 fell back to 50% for WZ, `measConvSF.py:60-70`, as the table has no WZTo3LNu_powheg entry): MATRIX NNLO QCD scale (+) PDF of the channels in our cross section (`AN-25-154/docs/CMS_MATRIXCrossSectionsat13p6TeV.md`, m_OSSF > 4 GeV; per channel 1.3-1.9%, weighted 1.6%). ZZ: MATRIX nNNLO scale (+) PDF, 4.2% (user 2026-11-27; the same source as its cross section; B2G 6.4%). The user is not sure a WZ N_jet SF (and its uncertainty) will be used in 2024, since the low-pT jet issue is resolved in NanoAODv15 (PLAN 3.5).
- **C5 (MC corrections in the CR):** ID SFs (ours), trigger SFs (T1), PU, b-tag weight for N_b = 0; no top pT weight. Proposed as written. **Decided (user 2026-11-27):** the DiLepton weights: MCweight x lumi x PU x electron reco SF (POG) x our muon and electron ID SFs x trigger SF (DblMu / EMu, T1) x b-tag weight method 1a (UParT medium). Not applied: top pT (search analysis), muon reco SF (TrackerMuons/GeneralTracks ~ 1 per MUO 2024, recommended only for high-precision analyses, not in the 2024 jsonpog `muon_Z.json.gz`; none in B2G Run 3 either), WZ N_jet SF (open, PLAN 3.5; ConvSF recomputed if it is introduced). The uncertainties of these corrections do not enter the ConvSF (as B2G).
- **C6 (scope of the analyzer port):** the TriLepton analyzer is written for SR, ZG CR and WZ CR at once (selections only; systematic lanes later), so that the conversion, WZ (PLAN 3.5) and SR work share one production. Proposed. **Decided (user 2026-11-27): (a)**, one C++ analyzer (no Python analyzer) for SR, ZG CR and WZ CR, Central lane first; **the SR data stay blinded throughout the feasibility study** (data events with all leptons tight in the SR are not written; nonprompt sideband and CR data are).
